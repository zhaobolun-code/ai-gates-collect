# ai-gates-collect

跨项目收集仓：各项目把「**项目典故** + **项目错题本**」中已确认可共享的条目上传到这里，经维护者审查合并后，抽象的通用级条目有机会进入 [ai-gates](https://github.com/zhaobolun-code/ai-gates) 技能包（通用典故 / 反模式），最终回传给所有使用 ai-gates 的项目。

## 你能做什么、不能做什么

| 能做 | 不能做 |
| --- | --- |
| fork 本仓、新增条目文件、发起 PR（任何人都可以，无需任何权限） | 直接改/删 main 分支内容（main 受保护：合并须审查，禁 force push，禁删除） |
| 在 issue 里贴草稿条目、讨论 | 删除别人已合并的条目 |

**合并 = 审查**：维护者合并你的 PR 时即完成一次审查（相当于 ai-gates 里的「准」）。条目入库后由维护者负责抽象升级与回传。

## 上传什么

1. **项目典故**：你的项目里验证过、可复用的结构（`design-patterns` 词条级，例如「命令（撤销）」「事件分发」）。放入 `典故/`。
2. **项目错题本**：踩过且改正过的坑（lessons 级，例如「疑问句只答不改文件」）。放入 `错题本/`。

## 条目要求（硬性）

- **去上下文化**：条目必须抽象到系统架构层（决策层 / 真源 / 对照 / 重设计）。**禁止**出现你本仓的窗号、场景名、文件路径、内部编号——那会让别人看不懂、也进不了通用级。
- **一条一文件**：每条一个 `.md`，文件名 = 条目标题（如 `命令-撤销.md`、`疑问句只答不改文件.md`）。
- **用模板**：`templates/` 下有典故与错题本两种模板，五格与错因/改正字段照填。
- **禁凑数**：没验证过的、只像不真的结构不上传。

## 流程

```text
fork → 建条目文件（按模板）→ PR → 维护者审查合并（= 准）→ 入库 → 抽象升级 → 回传 ai-gates
```

## 与 ai-gates 的关系

本仓是 [ai-gates](https://github.com/zhaobolun-code/ai-gates) 进化闭环的上传端：项目侧 `collect-queue.md` 的 `shareable` 条目可复制/导出到本仓；上传通道 = PR，合并 = 审查。gh 未接线之前 ai-gates 侧不上传/不下发，本仓直接收 PR 即可。
